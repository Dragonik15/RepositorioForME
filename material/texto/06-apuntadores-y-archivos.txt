6.1.      Operaciones con apuntadores
    Un apuntador es una variable que contiene una dirección de memoria. Normalmente, esa
dirección es la posición de otra variable que contiene un dato. Si una variable contiene la
dirección de otra variable, entonces se dice que la primera variable apunta a la segunda. El
apuntador apunta al espacio fı́sico donde está el dato o la variable. Un apuntador puede
apuntar a un objeto de cualquier tipo incluyendo estructuras, funciones, etc.

Un nombre de variable se refiere directamente a un valor y un apuntador se refiere indirecta-
mente a un valor. El referirse a un valor a través de un apuntador se conoce como indirección.

Si una variable en la posición 1004 está apuntada por otra variable situada en la posición
1000, la posición 1000 contendrá el valor 1004 como se muestra en la figura 6.1
    Los punteros permiten a las funciones modificar sus argumentos de llamada, se utilizan
para soportar las rutinas de asignación dinámica de C, mejoran la eficiencia de ciertas rutinas
y se pueden utilizar para crear y manipular estructuras de datos.

Si una variable va a contener un apuntador, entonces tiene que declararse como apunta-
dor. Una declaración de apuntador consiste de un tipo base, un asterisco ( * ) y el nombre
de la variable. La forma general de declaración de una variable apuntador es la siguiente

tipo *nombre;

    Donde tipo es cualquier tipo válido de C, el tipo base del apuntador, y nombre es el
nombre de la variable apuntador. El tipo base del apuntador define el tipo de variables a
las que puede apuntar. Cualquier tipo de apuntador puede apuntar a cualquier lugar de la
memoria, pero C asume que a lo que apunta un apuntador es un objeto de su tipo base.
Además, la aritmética de apuntadores está hecha en relación a su tipo base.

Existen dos operadores especiales de punteros: & y *.

& es un operador unario que devuelve la dirección de memoria de su operando. Por ejemplo,
observe la siguiente instrucción

6.2.      Tipos de archivos
    Existen dos tipos de flujos: de texto y binarios. Un flujo de texto es una sucesión de
caracteres. En un flujo de texto pueden ocurrir conversiones de caracteres, lo que ocasiona
que no haya una correspondencia uno a uno entre los caracteres que se escriben o se leen y
los que hay en el dispositivo externo. Un flujo binario es una secuencia de bytes con una co-
rrespondencia uno a uno con los del dispositivo externo. Esto es, no se realizan conversiones
de caracteres. El número de bytes escritos o leı́dos es el mismo que en el dispositivo externo.
El estándar ANSI especifica que se puede añadir un número definido de bytes nulos al final
del flujo binario. Estos números se pueden usar para ajustar la información de tal forma que
llene un sector del disco.

En el sistema de E/S del ANSI de C, un archivo es un concepto lógico que puede ser aplicado
a cualquier cosa, desde un archivo de disco a una terminal. Se asocia un flujo con un archi-
vo especı́fico realizando una operación de apertura. Una vez que el archivo está abierto, la
información puede ser intercambiada entre este y el programa. No todos los archivos tienen
las mismas caracterı́sticas, por ejemplo, un archivo de disco puede permitir el acceso directo,
mientras que un modem no, es decir, todos los flujos son iguales, pero no todos los archivos
lo son.

Si el archivo permite acceso directo, al abrir el archivo también se inicializa el indicador
de posición del archivo al comienzo del mismo. Según se leen o se escriben caracteres del
archivo, el indicador de posición se incrementa asegurando la progresión sobre el mismo.

La parte más pequeña accesible de un disco es un sector. La información del disco se es-
cribe o se lee sector a sector. Por tanto, aunque el programa sólo necesite un byte de datos,
se leerá un sector de datos entero. Estos datos se colocan en una región de memoria llamada
buffer hasta que puedan ser usados por el programa. Cuando se mandan datos a un archivo
de disco, se colocan en el buffer hasta que se acumula la suficiente información para llenar
un sector, en ese momento se escriben los daros en el disco.

Cuando se cierra un flujo, se escribe el contenido de su buffer asociado en el dispositivo
externo. A este proceso se le conoce como vaciado de buffer y garantiza que no quede infor-
mación accidentalmente en el buffer del disco. Todos los archivos se cierran automáticamente
cuando termina el programa, cuando main() devuelve el control al sistema operativo o me-
diante una llamada a exit(). Sin embargo es mejor cerrar un archivo usando fclose() en el
momento en que ya no se necesite.


6.3.      Almacenamiento de datos en archivos
   El almacenamiento de datos en variables y arreglos es temporal, al terminar un progra-
ma, todos estos datos se pierden. Para la conservación permanente de grandes cantidades de
datos se utilizan los archivos. Las computadoras almacenan los archivos en dispositivos de
almacenamiento secundario

Para facilitar la recuperación de registros especı́ficos a partir de un archivo, por lo menos un

Existen varias formas de organizar los registros dentro de un archivo. El tipo más popu-

C ve cada uno de los archivos como un flujo secuencial de bytes. Cada archivo termina

asocia un flujo con el archivo. Al empezar la ejecución de un programa se abren tres archivos
y sus flujos asociados, la entrada estándar, la salida estándar y el error estándar. Los flujos
proporcionan canales de comunicación entre archivos y programas

El sistema de E/S de C proporciona al programador una interfaz consistente e indepen-
diente del dispositivo al que se está accediendo. Es decir, el sistema de E/S de C proporciona
un nivel de abstracción entre el programador y el dispositivo que se está usando. A esta
abstracción se le llama flujo, al dispositivo real se le llama archivo.

El sistema de archivos de C está diseñado para trabajar con dispositivos, incluyendo termina-
les y controladores de disco. Aunque cada dispositivo es diferente, el sistema de archivos con
buffer transforma cada uno de ellos en un dispositivo lógico llamado flujo. Todos los flujos
se comportan de manera similar. Debido a que los flujos son independientes del dispositivo,
la misma función puede escribirse en un archivo de disco o de consola.

6.3.1.     Almacenamiento secuencial
    Un archivo organizado secuencialmente es un conjunto de registros lógicamente relacio-
nados cuya secuencia de acceso está determinada por su ordenamiento. Los registros deben
ser grabados consecutivamente cuando el archivo es creado, y deben ser leı́dos de la misma
manera cuando es usado posteriormente como entrada.

Los archivos secuenciales se utilizaban cuando el soporte de almacenamiento masivo más
usual era la cinta magnética. Hoy dı́a no es habitual encontrarse con archivos de organi-
zación interna secuencial. Pero sı́ que se utiliza el acceso secuencial, po su simplicidad y
utilidad. Si se necesita acceder a registros individuales y no consecutivos, el acceso secuen-
cial ofrece un rendimiento pobre y es preferible el acceso directo.

Los registros deben ser recuperados de un archivo secuencial en orden consecutivo. El orden
deseado para recuperar los registros debe dictar el orden en el cual deben grabarse.

El acceso secuencial se implementa con un indicador de posición que señala qué registro
fue el último que se accedió. Al abrir el archivo, el indicador se sitúa en el primer campo
del primer registro. Cada acceso sobre el archivo desplazará el indicador de posición hacia el
siguiente registro, hasta que ya no haya más registros que leer.

Cuando un archivo secuencial se abre para escribir datos en él, el indicador de posición
se sitúa justo después del último byte del mismo, de manera que los datos sólo se pueden
añadir al final.

6.3.2.     Almacenamiento directo
   Un archivo directo consiste en una colección de registros de longitud fija almacenados
uno al lado del otro en un dispositivo de almacenamiento de acceso directo. El almacena-
miento de este tipo de archivos se restringe a los discos por que el acceso a registros se hace
generalmente en orden aleatorio.

Se utiliza la forma directa cuando existe la necesidad de leer registros individuales direc-
tamente. En un archivo directo existe una relación predecible entre la llave usada para iden-
tificar un registro y su localización dentro del archivo. Sin embargo, el ordenamiento lógico
de los registros no necesita tener ninguna relación con su secuencia fı́sica. Los registros no
necesariamente aparecen fı́sicamente ordenados de acuerdo al valor de sus llaves.

Cada registro en un archivo de organización directo se puede referir por medio de una di-
rección, la cual indica su distancia o desplazamiento desde el origen del archivo. Al primer
registro en un archivo relativo se le asigna el valor 1, 2 al siguiente y ası́ sucesivamente. De
este modo, la dirección relativa de un valor entero que refleja su posición respecto al primer
registro del archivo.
